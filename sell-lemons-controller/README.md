# Sell Lemons Controller 4.0.5-dev

Модульная переработка приложенного **3.3.3**. Экономические формулы и каталог из 452 позиций сохранены; добавлены независимые наблюдения, ограниченное восстановление чтения, пересмотр стратегии по времени, новое меню, отдельный AntiIdle и публичная загрузка без токена.

**Статус: сборка для проверки в игре.** В живом логе найден источник состояния собственной базы: `Workspace/TycoonN/Values/Values`, а также `Values/Upgrades`. Независимый читатель выбирает базу по `Owner.Value == LocalPlayer`; номер слота не фиксируется. Счётчики эволюции/Halo/перерождений и уровни стендов доступны без открытия вкладок. Денежные поля проверяются по трём видимым отсчётам интерфейса: линейное число либо десятичный логарифм. Формат каждого поля проверяется отдельно. После проверки Cash может читаться из атрибута при скрытом HUD; при расхождении, смене владельца или счётчиков сброса проверка аннулируется.

В 4.0.3 обычные улучшения восьми стендов выполняются прямыми `Upgrade(count)` без мыши и открытия Manage. Пачки рассчитываются по 18 997 ценам из текущего клиента, с учётом уже купленных уровней, Halo и открытого UpgradeStack. Перед параллельной отправкой резервируется общий кошелёк. Результат подтверждается точным изменением каждого уровня в той же базе и цикле. Неизвестный результат останавливает проход без повторной покупки. Свежие потоки Income читаются без меню; временное рассогласование уровня и дохода остаётся неизвестным.

Распределение сначала обеспечивает доступное покрытие стендов, затем направляет остаток по наблюдаемой отдаче. Это ограниченная стратегия, не доказательство оптимальности. Сигнатуры и таблицы сверяются с байткодом текущего клиента без его выполнения. Изменение игры или неизвестные эффекты InversionCards останавливают прямые покупки. При загрузке в журнал печатается `[SL HEADLESS]`; повторить отчёт можно через `print(getgenv().SLAutofarm.directReport())`.

В 4.0.4 добавлены прямые **Powers и Buy**. Powers покупаются за инвесторов через подтверждённый обработчик `UpgradePowerLevel(name, 1)`, с сохранением суммарного защищённого банка. Обычный Buy выбирается по 453 внутренним идентификаторам и порядку из текущего Balance, проверяет цену, доступность и оставшиеся использования Remote Buy; запрос `Purchase(true, false)` не тратит forever purchase. Каждая следующая постройка читается заново после подтверждения предыдущей. Прямые покупки не требуют Manage; старое удержание кнопки Buy для них отключено.

Исправлена остановка 4.0.3 на `INVERSION_PRICE_STATE_UNAVAILABLE`: прочитанный InstanceTable создаёт пустую отсоединённую Configuration, пока InversionCards не реплицирована. В текущем Main без инверсии отсутствие папки поэтому означает отсутствие карточных эффектов. Положительная инверсия без данных и неизвестные непустые карточки по-прежнему блокируют расчёт цены.

**Граница реализации:** выполнение сбросов, чтение награды следующего rebirth и готовности evolution ещё используют меню. В игре подтверждён отдельный прямой апгрейд `LemonStand 2 → 3`; 4.0.3 в полном запуске остановилась до апгрейдов из-за проверки InversionCards. В 4.0.4 журнал подтвердил две покупки UpgradeStack и покупку Windows через прямые вызовы. Полная пачка улучшений стендов ещё не подтверждена в игре. 4.0.5 исправляет сохранение блокировки покупки после внешнего сброса; этот переход проверен офлайн на воспроизведённой последовательности отказ → эволюция → новая покупка. Не заявляется полностью фоновый цикл Halo.

В 4.0.2 исправлена ошибка финального прогноза, подтверждённая логом 05:43:58: сценарий будущих бонусов принудительно включал FINISH, обходя `AllowConditionalFinish=false`. Теперь расчёт сначала оплачивает текущую наблюдаемую покупку, затем моделирует будущие бонусы; ×10 применяется только после оплаты. Неизвестный порядок дальнейших открытий остаётся допущением. Сценарий больше не объявляется гарантией финала и не подавляет готовую эволюцию. Действующий FINISH повторно проверяется по свежему доходу и цене; исходный срок не продлевается мелкими покупками. При расхождении запрашивается сравнение продолжения, rebirth и evolution, а не безусловный сброс. Уже оплачиваемый остаток можно завершить без лишнего сброса. Девять регрессионных групп пройдены офлайн; новый проход в Roblox пока не проверен.

По первому игровому логу исправлена повторная проверка исходной Rebirth-кнопки после открытия подтверждения: на этом этапе проверяется соответствующая кнопка диалога, а финансовые ограничения остаются. Сценарий проверен офлайн; успешное перерождение с исправлением в игре ещё не подтверждено.

## Запуск без токенов и ключей

Репозиторий `skeetels/glua` публичный. Выполните одну строку:

```lua
local s=type(request)=="function" and request or http_request;assert(type(s)=="function","HTTP request unavailable");local r=s({Url="https://raw.githubusercontent.com/skeetels/glua/main/sell-lemons-controller/dist/controller.lua",Method="GET"});assert(type(r)=="table" and tonumber(r.StatusCode or r.Status)==200,"GitHub HTTP request failed");local f,e=loadstring(r.Body);assert(type(f)=="function",tostring(e));f()
```

После появления панели нажмите **Запуск / F6**. F7 — журнал, F8 — скрыть/показать. Кнопка «Закрыть» останавливает контроллер и отключает его подписки. Требуются `request` либо `http_request` и `loadstring`. В текущем Xeno `game:HttpGet` завершился ошибкой до компиляции, поэтому публичный загрузчик использует `request` и проверяет HTTP-статус.

При запуске скачивается одна цельная актуальная сборка, поэтому версии модулей не смешиваются. GitHub-токен и заголовок Authorization не используются. `loader/one-line.lua` содержит ту же строку. `loader/private-loader.lua` сохранён как прежний вариант; для текущего публичного запуска он не нужен.

Новый читатель включается автоматически. В логе появятся `DATA_SOURCE`, `DATA_SNAPSHOT` и, после успешной сверки, `DATA_ENCODING_VERIFIED`. `print(getgenv().SLAutofarm.dataReport())` выводит точечный отчёт; этот же отчёт включён в журнал F7. Прямой адаптер использует подтверждённый формат Cash log10 после сверки схемы игры. Investors сохраняет отдельную сверку.

Для следующего этапа доступен отчёт `print(getgenv().SLAutofarm.inspectData())` после загрузки актуальной панели. Он ограниченно осматривает LocalPlayer, ReplicatedStorage и явно принадлежащий игроку Tycoon. Модули и сетевые объекты перечисляются только по именам; меню не открываются, модули не выполняются, сетевые методы не вызываются. Поля не подключаются к стратегии автоматически. Достижение лимита явно помечается и не означает отсутствия данных.

Диагностику можно запустить отдельно, без перезапуска работающего контроллера. Она делает два снимка с интервалом три секунды и печатает их в лог Roblox:

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/skeetels/glua/main/sell-lemons-controller/dist/inspect-data.lua"))()
```

## Запись действительного вызова апгрейда

Для реализации действий без окон нужна сигнатура реального вызова, а не предположение по имени RemoteFunction. Поставьте фарм на паузу, запустите запись и один раз улучшите обычный стенд вручную:

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/skeetels/glua/main/sell-lemons-controller/dist/trace-upgrades.lua"))()
```

Инструмент на 90 секунд записывает существующие `FireServer` / `InvokeServer` только внутри базы, чей `Owner.Value` совпадает с LocalPlayer. Он не отправляет и не повторяет игровые запросы. В логе появляются `[SL ACTION] CAPABILITIES`, затем `LISTENING` либо точная причина неподдержки. Локальный тест перехвата не доказывает видимость вызовов игровых скриптов — это устанавливается только по реальному `CALL`. Изменение уровня отмечается отдельно как временная связь, не как доказанный результат конкретного запроса. Поля token/password/secret/cookie скрываются.

`getgenv().SLActionCapture.stop()` завершает запись раньше. При наличии более позднего стороннего перехвата инструмент не перезаписывает его; собственный слой остаётся неактивным сквозным вызовом. Эта диагностика не включена в основной контроллер и не является готовым режимом прямых покупок.

В Xeno пользователя 05:58:20 получено `hookmetamethod=false`, `getnamecallmethod=false`, `decompile=true`, `getscriptbytecode=true`: перехват недоступен. Альтернативный `dist/inspect-client.lua` читает текст до десяти клиентских обработчиков через `decompile`, перечисляет сетевые объекты собственной базы и внутренние имена стендов. Запуск через `request` проверен в живом логе. Однако декомпилятор не поддерживает текущий байткод v12; обновлённая диагностика в этом случае выводит байткод пяти выбранных обработчиков для локального разбора (до 32 КиБ на модуль, до 128 КиБ всего). Ничего не покупает, модули и байткод не запускает, перехваты не устанавливает. Для запуска замените `dist/controller.lua` в строке выше на `dist/inspect-client.lua`. Лог подтвердил внутренний `LemonStand` при отображаемом Lime Stand; имена не заменяются наугад.

## Устройство

`dist/probe-direct-upgrade.lua` — отдельная одноразовая проверка найденной сигнатуры. Версия v3 останавливает прежний контроллер и отправляет по одной попытке `+1` собственным открытым стендам, параллельно и без загрузки игровых модулей. Наличие денег проверяет сервер: это проверка транспорта, а не распределение бюджета. Подтверждением служит изменение реплицированных уровней в той же базе и цикле; неизвестный результат не повторяется. Затем читаются байткоды зависимостей расчёта цены, без выполнения. Это не включённый в основной фарм режим и не новая стратегия постоянных `+1`. Для запуска замените путь файла в публичной строке загрузки; инструмент действительно пытается совершить эти небольшие покупки. Пока он не завершился, основной контроллер запускать не следует.

| Папка | Ответственность |
|---|---|
| `src/core` | Большие числа, прогнозы, политика восстановления, свежесть наблюдений |
| `src/data` | Сохранённый каталог |
| `src/adapters` | Чтение GUI, навигация, проверенные исходником способы ввода |
| `src/strategy` | Выбор улучшений, банк инвесторов, прогноз сброса, маршрут Halo |
| `src/runtime` | Единственный исполнитель, подтверждения, жизненный цикл, наблюдения, AntiIdle |
| `src/ui` | Отображение прогресса и управление |
| `loader` | Публичный запуск одной строкой; прежний приватный загрузчик |
| `tools`, `tests` | Воспроизводимая сборка и офлайн-проверки |

Каждый модуль — обычная функция инициализации с явным контекстом зависимостей. В рабочем коде нет подмены окружения через `setfenv`, динамического скачивания отдельных модулей или обфускации. `manifest.json` задаёт порядок. `dist/controller.lua` генерируется; редактируют исходники в `src/`. Полный переход от общей структуры контекста к изолированным сервисным интерфейсам ещё не выполнен: существующая стратегия намеренно перенесена без переписывания всех её формул за один раз.

## Изменения поведения

- Повторное чтение неизменившегося скрытого текста не обновляет его возраст. Изменение скрытых значений может запросить проверку, но не разрешает сброс само по себе.
- Подтверждённый сброс аннулирует предыдущие наблюдения.
- В PREPARE стратегия пересматривается не реже 45 секунд при доступном исполнителе; число покупок +1 не может бесконечно откладывать проверку. Это интервал **проверки**, а не фиксированный множитель для rebirth. Незавершённый проход сохраняется. FINISH, восстановление после сброса и незавершённые транзакции сохраняют свои ограничения.
- Пять конкретных ошибок временной недоступности меню/данных допускают до четырёх повторов с задержкой 1/2/4/8 секунд. Подтверждённый прогресс сбрасывает счётчик. Ручная пауза отменяет восстановление. Ошибка покупки, неизвестный ответ и ошибка выполнения автоматически не повторяются.
- AntiIdle подписывается на `Player.Idled` и пробует отдельную пару событий VirtualUser. Он не отключает обработчики игры и не работает одновременно с экономической транзакцией. `INPUT_SENT_UNVERIFIED` означает только вызов API; отсутствие AFK-кика не подтверждено.
- Панель имеет масштабирование, прокрутку длинного прогресса, перетаскивание и отдельный переключатель AntiIdle.

## Проверка и ограничения

```powershell
python tools/build.py
python tools/build.py --check
python tools/test.py --luau-dir C:\path\to\luau
```

Нужны Python 3.10+ и `luau` / `luau-compile` из официального [Luau](https://github.com/luau-lang/luau). Тесты не скачивают и не исполняют сторонние хабы. `dist/integrity.json` содержит SHA-256 сборки и исходников для контроля воспроизводимости, а не отдельную цифровую подпись.

Проверяются свежесть/аннулирование данных, сохранение прохода при временном сбое, ручная отмена, запрет повторов неоднозначной покупки, своевременный пересмотр, ограничения FINISH, загрузчик с поддельными ответами HTTP, инициализация/диагностика/отключение подписок на минимальном макете движка. Макет не имитирует серверные покупки, физику, свёрнутое окно или реальное время AFK. Полная статическая типизация старой динамической стратегии не пройдена; отдельно выполнена именно компиляция Luau.

Актуальные результаты проверок и подтверждённые строки игрового лога перечислены в `VALIDATION.md`. В интеграционной проверке используются заглушки движка. В рабочей сборке три цикла: единственный исполнитель экономических действий, независимый наблюдатель без действий и обновление панели.

До заявления о полной готовности остаются живые проверки:

1. Проверка актуальной публичной сборки через `request` в вашей Lua-среде.
2. Получение нового GUI и работа кнопок; покупка → появление реального уведомления → подтверждение → продолжение прохода.
3. Сценарий долгих +1, оценка выгоды rebirth по свежему доходу и времени восстановления, сохранение эволюции.
4. Работа в фоне и проверка AntiIdle в течение реального периода простоя.
5. Поиск фактического клиентского источника данных и подтверждение, что он продолжает обновляться при закрытых вкладках. До этого обещать режим полностью без меню нельзя.

Ссылка Acro из запроса была прочитана как текст, без запуска. Она перенаправляет на GitHub-загрузчик, затем Luarmor; открытой логики Sell Lemons в этих двух файлах нет. Она не доказывает конкретный механизм или совместимость этого проекта. Обход ключей Acro в проект не включён.

В 4.0.5 счётчики реального сброса отделяют старый цикл от нового. Неподтверждённые запросы прошлого цикла снимаются с блокировки, но не засчитываются успешными. Внутри того же цикла блокировка остаётся; уже выполняющийся запрос не освобождается. После rebirth сохраняется учёт потраченных инвесторов. Начальный отчёт печатается отдельными строками, чтобы Roblox не обрезал сведения Buy/Powers.
